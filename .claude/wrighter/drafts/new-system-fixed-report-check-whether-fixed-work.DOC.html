A New System Fixed the Report. Check Whether It Fixed the Work.

By Sunil Jith S H · For HMIS system administrators and CoC executive and program leadership

Three organizations closed the door on us this year for the same reason. Each had just finished migrating its HMIS. New system live, reports coming out clean, question settled, and no appetite for a conversation about operations for a full cycle. Three organizations is three organizations, so read that as an observation and not a trend.

The reasoning holds as far as it goes. A migration is expensive and disruptive, and clean reports at the end of one mean something real got fixed. What got fixed was the reporting layer. Whether the work got better is a separate question, and nobody on those selection committees had been asked it.

What a Migration Replaces

Start with the guidance a Continuum of Care works from when its HMIS changes underneath it. HUD's HMIS Data Collection Requirements for Transition to FY 2026 HMIS Data Standards, dated October 2025, runs to two pages. It carries a table of thirteen data element rows, and that table has exactly one instruction column, headed Data Entry Requirement.

Read all thirteen rows and you learn precisely what your staff must now type, for which clients, from which date. You learn nothing about whether they can type it in one place.

The pattern holds one level up. HUD's HMIS Guides and Tools library files every resource it publishes under six headings.

Section heading in HUD's HMIS Guides and ToolsWhat it governs
HMIS Data and Technical StandardsThe record's required shape
HMIS Data QualityWhether the record is complete and accurate
HMIS Leads and GovernanceWho is accountable for the record
HMIS Privacy and SecurityWho may see the record
Project Setup and Data Collection ResourcesThe configuration that produces the record
Vendor Programming and Data Exchange ResourcesThe reports that come out of the record

All six govern the record, from its required shape through to the reports that come out of it. None governs the job that produces it. HUD's framing on the FY 2026 HMIS Data Standards page states the order out loud: the purpose of correct configuration is that "proper project setup and data collection will help ensure accurate project and system-level reporting."

Reporting is the terminal outcome there, and everything before it is a means. A committee that reads this guidance and concludes a clean report is the finish line has read it correctly. That is the problem worth naming.

The Migration That Published Its Own Scope

One county-level HMIS migration has its transition material in the public record, which makes this checkable. We describe it by type instead of naming it, because the argument needs the fact of publication and nothing else about the jurisdiction. The published scope splits into three countable parts.

Eleven software requirements. One names a step in a case manager's job: a closed loop referral system. A second asks for customizable interfaces, and specifies their purpose as maximizing data collection and input efficiency, which illustrates the ordering under discussion. The other nine cover report generation, HUD exports, access permissions, browser support, and administrative tooling.

Nine vendor services making up the migration. Installation, hosting, interfaces, HUD-mandated and local reports, a phased implementation plan, a data migration plan, training, backup and recovery, and data quality recommendations. Every one is real work a migration needs. None of the nine is a test against the job.

Nine areas the implementation plan had to address. Timeline, organization chart, dedicated resources, software and hardware, acceptance testing criteria, training plan, preventive maintenance, backup contingency, and security. The fifth is where a test against the work would have lived. Those criteria were left for the vendor to propose.

The Case a Committee Can Fairly Make

Set out properly, the opposing argument is strong. Data entry conformance is exactly what HUD holds a Continuum of Care accountable for. Under 24 CFR 578.7(b), a CoC carries five HMIS obligations, and one of them is to review and approve a data quality plan. That plan is a named regulatory artifact. HUD's HMIS Data Quality Plan Worksheet organizes it around four principles: timeliness, completeness, accuracy, and consistency. The Annual Performance Report goes to HUD every operating year through Sage.

A committee scoping a migration to the compliance obligation is scoping to the thing it will be measured on. Widening that scope into a workflow redesign adds cost, schedule and political risk to a project already carrying plenty of all three. It also invites a fair objection: specifying how staff work narrows the vendor field toward whoever already builds that way.

The committee in the published case also put hands on the software. A test demonstration site was open to it for four weeks, and the final phase was a live system demonstration. Nobody bought this sight unseen, and none of it is negligence.

Where the Reading Goes Wrong

The obligation is real and this argument does not ask anyone to trade it away. Two things sit alongside it.

First, "optimize for data entry" specifies an output. Specifying an output leaves the path to it open, and the path is where staff either work inside the system or work around it. A program can produce an immaculate APR while referral chasing and document tracking both live in a spreadsheet, because the APR reads the record and cannot see how the record got there. Specifying the output is how a program arrives at a system its staff do not work in, which is the same failure as the system being retired.

Second, the regulation that creates the HMIS obligation creates another one immediately after it. Under 24 CFR 578.7(c)(1), the Continuum must coordinate the implementation of a housing and service system covering, at minimum, outreach, engagement and assessment; shelter, housing and supportive services; and prevention strategies. Three components of a working service system, required by the same rule, in the same section, of the same body that requires the data quality plan.

A migration scoped to 578.7(b) discharges all five of those obligations and touches none of the three in 578.7(c)(1). Both paragraphs are HUD requirements. A committee that treated the first as the whole of both did not misread its accountability. It read half of it.

The Test You Can Run on a System That Is Already Live

This needs no procurement and it works on a system that went live last quarter. Take one recently closed case, sit with the case manager who owns it, and walk it forward in the new system in front of you.

  1. Open a new intake and record the vulnerability assessment, from the first conversation through to a saved client record. Note every tool touched that is not the HMIS.
  2. Collect and attach the documents the program requires: ID, income proof, disability verification, consent. Then find where the checklist tracking what is still missing actually lives.
  3. Make a referral to a partner agency and record it. Then establish, inside the system, whether it was accepted, declined, or never answered.
  4. Record an assessment and a progress note on the same client on the same day, without re-entering anything captured at intake.
  5. Hand the case to a second staff member and ask them what happens next, using only the system.

Count the exits. An exit is any moment the case manager leaves the system to finish a step: a spreadsheet, an email thread, a PDF, a message to a partner, a paper form, a notebook. A clean APR will not give you this number, because the report reads the record and never sees the route it traveled.

Exits countedWhat it meansWhat to do next
0 The migration fixed the work as well as the report Write the walkthrough down and make it the acceptance test for the next system
1–2 A workaround has quietly become policy Name the two gaps and close them as a configuration change, not a procurement
3+ The reporting layer was replaced and the work layer was not Scope the work layer deliberately, alongside HMIS rather than instead of it

Three or more is the outcome a clean first APR most reliably hides. The reporting cycle after a migration tends to be calmer than the one before it, because the data got cleaned during the move. That calm is a one-time benefit of the move, and reading it as evidence about the workflow is how a committee closes the file.

If the Count Comes Back Above Zero

Nothing here argues the migration was wrong. A CoC has to run a designated HMIS that produces a defensible APR, and a system that cannot do that has to be replaced. The narrower claim is that the migration answered the reporting question and left the operating one open.

The practical move is to stop asking the HMIS to be two systems. It exists because HUD requires a database and requires reports out of it, and it is generally good at that. Moving one person from crisis to stability has a different shape: sequenced tasks, chased referrals, expiring documents, and continuity when staff turn over. We made the architectural case for that split in our webinar on why most housing systems were built to report rather than to run. If your next reporting cycle also worries you, our walkthrough of where APR and CAPER reporting breaks down for housing nonprofits traces that symptom to the same root, and our comparison of the 2026 HMIS strategy options shows where each platform sits.

Run the walkthrough before the next competition cycle. It costs an afternoon, and it answers the question the committee was never handed.
